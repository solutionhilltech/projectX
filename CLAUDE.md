@AGENTS.md

# ProjectX

Agent dashboard that scouts local businesses, generates a redesigned website
mockup for each, and delivers it over WhatsApp. See `README.md` for setup and
the user-facing description; this file covers what you need to change code safely.

## Shape of the thing

Next.js App Router, MongoDB, no job queue. The pipeline is three steps and each
API route runs its whole step synchronously inside the request:

```
/api/search    LLM search plan → places provider → save    (SSE stream to the UI)
/api/redesign  crawl+screenshot → vision brief → Stitch → persist → WhatsApp
/api/whatsapp/send  send an already-generated redesign
```

`src/proxy.ts` gates every route on a session cookie; only `/`, `/login` and
`/api/auth/login` are public. `src/lib/store.ts` is the only data layer — there
is no local JSON fallback, everything is MongoDB.

## Conventions

- **Self-checks, not a test framework.** Non-trivial pure logic exports a
  `runXSelfCheck()` beside the code it checks, and `scripts/test-*.ts` runs it.
  Follow that instead of adding Jest/Vitest.
  `scripts/test-stitch.ts` must run under plain `node`, not `tsx` — it imports
  the ESM-only `@google/stitch-sdk`, which tsx's CJS resolver cannot load.
- **Adding a setting touches four places**: `SettingsForm` in `lib/types.ts`,
  `DEFAULT_SETTINGS` and the env-fallback in `getSettings` (`lib/store.ts`), and
  the form state in `components/dashboard.tsx`.
- Settings resolve as *stored value → env var → empty*. Never read a user-facing
  key straight from `process.env`; go through `getSettings()`.
- `AGENTS.md` is regenerated by `next dev`. Leave it alone; commit it with your
  work if it shows up dirty.

## Google Stitch (`src/lib/stitch.ts`)

This integration is full of things you cannot infer from its error messages,
which are uniformly generic ("Request contains an invalid argument", "Something
unexpected happened"). Before changing it, know:

- **A design system must exist before generating.** Stitch cannot generate into
  a bare project — its own UI always builds "the visual foundation" first. This
  was the cause of every generation silently failing. Order is
  `createProject → createDesignSystem → update_design_system → generate`.
- **`create_design_system` needs a complete `theme`**: all five of `colorMode`,
  `headlineFont`, `bodyFont`, `roundness`, `customColor`. A partial theme is
  rejected.
- **`styleGuidelines` is a lie.** It exists on the SDK's `DesignSystemInput`
  TypeScript type but the server rejects it. Free-form direction goes in
  `theme.designMd`.
- **The SDK's font enum is stale** relative to the live API — the server accepts
  fonts its literal type does not. Hence the single cast at the
  `createDesignSystem` boundary; `normalizeTheme()` is the real guard.
- **Never retry `generate_screen_from_text`.** Stitch's tool docs say so
  explicitly. A response with no design means it's still running — poll
  `list_screens` every 30s (up to 10×) instead. `create_project` *is* safe to
  retry, and needs it: it intermittently rejects valid input.
- **Generation may answer conversationally** with `text`/`suggestion` instead of
  a design. Accepting the suggestion as the next prompt is the documented way
  forward; treating it as failure is wrong.
- **Model-authored theme tokens must be normalised** (`normalizeTheme`) before
  they reach Stitch. One hallucinated font name fails the entire call.
- Stitch returns supporting imagery (square tiles, banners) alongside the real
  page render. `pageLikeScreens()` filters on aspect ratio — a heuristic, marked
  with a `ponytail:` comment.

## Other traps

- **Screenshot image URLs**: append the screen's own `width`/`height` as a FIFE
  size suffix, and do *not* double it. Tall mobile designs (e.g. 780×8636) blow
  past the image server's pixel budget, which returns an HTML error page instead
  of an image, and WhatsApp then fails with Meta error 131053.
- **Puppeteer** uses a full local Chrome in dev and `@sparticuz/chromium` when
  `USE_SERVERLESS_CHROMIUM=true` or `process.env.VERCEL` is set. Neither Docker
  nor Vercel can download Chrome at runtime.
- **`/api/redesign` takes 2–3 minutes** and declares `maxDuration = 300`. On a
  hosting plan capped below that, it is killed mid-generation. Railway (a normal
  long-lived process) is the safer target.
- A redesign auto-sends on WhatsApp when it succeeds. **When testing against a
  real business record, that message goes to a real phone number.** Use a test
  record with `phone_number: null`.
